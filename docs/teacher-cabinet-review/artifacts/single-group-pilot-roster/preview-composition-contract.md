Do not add a second preview function. They validate the echo, reject self, and emit only group_names and an opaque handle or null. The handle binds actor, exact student/ID, group, subject, revisions, epoch and 120-second expiry. Correct request ordering is already implemented; actual authority, durability and store isolation are not.

1. Construct the request-owned context from verified current Clerk/person plus canonical locked current staff/Teacher approval, configured real subject and active group. No caller actor/subject/group claim may become authority. Maintain the request's exact AbortSignal and liveness before return. A separate current attempt/ledger read cannot be presumed complete if access is filtered.

Do not reset/refund quotas on misses, malformed IDs or client abort, and do not use an in-memory counter. The existing caller already charges before parsing digits (valid and invalid admitted requests), so retain that anti-enumeration behavior.

No substring, cast-to-number, partial match, export, list, profiles/names, user IDs or browser DB query. Preserve the user's agreed group_names output only and no distinction for missing, invalid, non-Student, disabled or self beyond the canonical rejection.
