# Teacher exact cabinet-ID preview and confirm: unmounted domain contract

Requires the corrected Teacher group-add planner (exact current own-group grant, no generic Admin flag). The ID parser follows pinned student-state.ts::newQadamId and the unique text column: exactly ten ASCII digits; a string preserves leading zeros, numeric input is accepted only when already ten digits (never pad, round or guess). URL and public aliases are not used by this seam.

Preview authenticates current Teacher and explicit active own group before consuming the server-owned lookup quota and querying one exact cabinet ID. Verifies that the bound reader returned that exact canonical value and that enabled existing Student's complete true pair snapshot. Names are read solely from current active group rows and every displayed label must actually exist; the response is only group_names and an opaque presence-bound confirmation handle. Never disclose student UUID, peer IDs, group IDs, grades, account fields, archived names or raw lookup input. No singleton affinity fallback. The injected future storage needs a verified complete pair read and an atomic membership-set tag covering the preview state; a current single-affinity reader is not composable.

Confirmation must resolve an opaque server-recorded binding for the same Teacher/target/Student/snapshot and in-window expiry. Intended wire handle is a CSPRNG 256-bit random Base64URL value (43 characters) backed by trusted ephemeral server state, not readable signed claims, identifiers in URLs, or an auth credential. The code only validates shape; a trusted issuer/verification store, canonical clock and rate policy are still mandatory before wiring. Proposed TTL is 120 seconds. At confirmation, rule-check under already acquired canonical Teacher/Student/target-group locks, re-read complete current snapshot and delegate to the one-pair planner. No write, invitation, role change or handoff.

Static strict forward/reverse patch apply, exact bytes and stripped TypeScript syntax only. No data, fixtures, live SQL, deployment or push.
