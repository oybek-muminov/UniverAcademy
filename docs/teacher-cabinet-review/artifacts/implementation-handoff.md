# Teacher cabinet auto-routing: local implementation handoff


## Scope

One Clerk registration/login and one existing person. Preserve student role and history. No chooser and no teacher-to-student switch UI for this release. Cabinet normally opens Teacher when the current account has confirmed teacher access; otherwise the current Student path. An existing unfinished attempt stays in Student, with the same session, answers and original deadline. Uncertain eligibility never opens Teacher. This is a navigation policy, not a grant or authorization source.

## Confirmed source behavior and boundary

- `apps/mini-app/src/telegram-atomic-entry.tsx:31–36` mounts `AccountDeletionHost → StudentApp` on ready. Keep this subtree intact for Student.
- `telegram-atomic-runtime.ts` builds a new StudentFlow on open; matching authenticated person is checked. In-memory `flow.snapshot().attempt` is reset by enter and cannot prove there is no resumable attempt on a fresh launch. Some Telegram resumes have no current Clerk session in the WebView; require only the app's already validated student continuity proof for the read if Backend accepts that contract; never make the launch re-link or mint a new family.
- Canonical `contracts/telegram-return.openapi.json` contains `Profile.roles`, but it does not carry staff approval, scope, or fresh provider state. `wire-map.ts:55–59` drops the roles in the Mini App presentation model. Do not add fields to the pinned profile or use its role as Teacher authorization.
- `student-http.ts:186–192` lists only visible assignments and may materialize expiry. The Mini App's `wire-map.ts:21–26` drops `series.current_status`. Neither absence from `/exams` nor the local store can exclude a still-resumable active attempt. Do not add a per-exam client fanout to decide routing.
- `runtime/cloudflare-entry.mjs` accepts only a registration route set plus explicit atomic-entry and deletion handlers. There is no live Teacher navigation endpoint in that entrypoint. `staff-access-rows.ts` can read the current Clerk-backed staff record in a scoped transaction, but it is not a route/adapter. Teacher browser boot deliberately uses `unconfiguredPort`. The staff OpenAPI is provisional and does not implement appointment/revocation or Teacher profile/group/test live reads. Do not invent fallbacks or approval mutations.

## Minimal paired patch after Backend owner acceptance

1. Backend owns a new read-only endpoint, suggested `GET /api/v1/me/cabinet-access`. Suggested minimal strict response carries existing `person_id` and an enum `default_cabinet: student | teacher`. Navigation subject derives from the trusted session, never URL/query/header person ID. An atomic, person-scoped, read-only DB view checks current enabled identity, confirmed teacher role/approval under canonical policy, and authoritative resumable attempt status using an existing canonical attempt/liveness rule and server time. No counts, draft data, admin grants or scopes leave this endpoint. A missing/ambiguous active-attempt proof is not teacher eligibility. No new family, writes, migrations, existing auth changes or fixture wiring. Use existing origin/CORS and no-store headers. A deployment gate is external to this local design.
2. Mini App requests this separately using a bounded, cancellable read. Capture ready runtime/flow instance, current person, authenticated session generation where available and monotonically increasing request sequence; before applying a late result recheck all. Reuse the same Student subtree and transport for Student, including account deletion. If the user has already interacted with the Student app, a late result must not switch it underneath them; gate before interactive mode, or commit Student as the attempt user's safe per-entry default on timeout. Navigation resolution must not re-run `login`, link Telegram, mutate roles, clear the Student family, or reinitialize `StudentFlow`.
3. Teacher browser target must be an existing configured trusted route. Never transfer Telegram initData, Clerk JWT, refresh tokens, or person IDs in URLs for navigation. In an external browser, use its independently valid Clerk session and resolve the same existing person; never accept silent mismatches, email/name matching, or a new teacher identity. If no valid same-person browser session is established, use the reviewed existing sign-in flow or keep Student; do not treat seamless cross-container auth as proven. The Teacher adapter itself reads verified API data and every Teacher endpoint independently checks current role, approved status, liveness, and subject/group scope. Clear authorized Teacher state after revocation/account switch and restore Student via the existing continuity path only if valid.
4. The admin/owner appointment and revocation operation is a separate Backend/product dependency. No raw UPDATE, improvised role mutator, or permission change is part of this patch.

## Real-account release checks (not performed)

Before appointment Student opens directly. After an authorized appointment Teacher opens by default and Student history remains intact. Appointment during an active test, including reopen in a different browser/device, must not steal the attempt; existing timer/answers/IDs stay unchanged. After legitimate revocation, direct Teacher URL/API denies and current Student access remains. Check timeout, aborted role resolution, account switch/stale response, Clerk browser session mismatch, same authenticated subject mapping, no extra family and existing Student account-deletion flow. Only designated real data; keep these checks out of unauthorized production mutations.
