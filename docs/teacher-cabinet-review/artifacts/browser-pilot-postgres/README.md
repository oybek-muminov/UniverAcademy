# Teacher browser pilot: Postgres locked read composition

Pinned project base 3dbb714f2f758c7dbe03548a71c161718cf9cb53. Requires the separate browser-pilot handler and Teacher bootstrap candidates. This addition composes their actual dependencies, but registers no Worker route and loads no production configuration.

The new PostgresTransactions.runClerkRead uses the existing trusted transaction shell and canonical Clerk lock order used by ClerkScopedAuthStore: identity advisory lock via clerkIdentityKey, lock_clerk_identity for exact existing enabled mapping, then existing exact single-person lock. It rejects absent, disabled or ambiguous mapping; it never creates accounts or invokes staffOrLink, ClerkAuthRows.flush, auth exchange or session replay processing. The composition rechecks issuer/subject/person under that lock, enters the established domain phase, passes actual DB clock, restricts the minimum browser token/current provider expiry, and retains cancellation and before-commit checks. Ordinary browser pilot GET is untouched while dependencies remain unwired. The routine does not use a SQL read-only transaction because the canonical authority helper uses row locks; the operation itself does not mutate data, and the required storage role and real metadata bridge must guarantee that boundary.

Still needed before any release: an explicitly approved existing or new role authorized for exactly Clerk identity/person locking plus Teacher staff/approved subject/group reads (Student-only ua_runtime is insufficient; do not reuse deletion credentials), independently verified RLS and scope, complete canonical names/allowed test metadata, trusted canonical HTTPS route/Clerk configuration, and actual real-account verification. Metadata is injected under the checked lock, not synthesized. No account-link/Student family mutation or external-browser handoff.
