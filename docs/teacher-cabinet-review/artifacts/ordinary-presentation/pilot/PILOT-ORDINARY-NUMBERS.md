It implements the Architect-reviewed 0–100 percentage display as exact BigInt HALF_UP2, without multiplying by 100 twice; the prior approved exact HALF_UP1 earned/max display stays. The candidate validates existing stored exact earned/max/percentage against each other, without reading answers or computing a new score. Existing attempt, ordinary calculation, storage, review, Rasch, bonus, Teacher/Excel display and Worker defaults do not change.

Required actual pilot input: Owner-approved **one real group ID, stable demo ID, exact immutable published version ID** and the existing authorized, already committed Student ordinary result for it. The original published snapshot supplies question count and exact base amounts: 1/question when individual scoring is disabled; otherwise existing canonical positive maximum 30 and 3-decimal validation. Maximum is derived from exact thousandths, not hardcoded 30 or guessed test limits. The accepted legacy numerator/denominator bounds are derived from that snapshot; binary64 output uses exponent and quotient/remainder BigInt integer rounding to a representable significand, with tie-to-even only for the approximate legacy JSON `number`, never the displayed strings. No float-first/double display rounding, clipping, fallback zero/null, or unchecked Number(numerator)/Number(denominator).

`projectPilotOrdinaryResult` only accepts the selected stored attempt and refuses a stored bonus; it calls the existing `scoreWire`. Integrate only into an existing authenticated and already committed read/receipt completion render with the request's exact authorized pilot pin; no default numeric configuration or scope inference. Before accepting a pilot route, validate with Owner-approved actual immutable record after commit, compare own earned/max/percentage and display against exact computation, confirm same receipt/replay outcome plus no bonus data/no score writes from presentation. An unavailable/mismatched pin, noncanonical ratio/range, or unavailable real pilot snapshot means disabled; actual test IDs and publication not supplied here. No synthetic tests, deployment or live changes.
