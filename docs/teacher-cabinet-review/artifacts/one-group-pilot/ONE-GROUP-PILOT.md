# One real Fizika group: minimum pilot path

Scope: one named real Fizika subject, one named existing enrolled group, one authorized existing Teacher, one or more owner-designated real registered Students, one manually authored real test; no appointment, multi-group, public, bonus, Rasch, Telegram invite or channel gate. Future features are not reverted. No staging/deploy/SQL/credential action performed.

## Existing connection points and the patch

1. Browser staff calls need independent current Clerk proof. `clerk-http.ts` coordinates `currentStaff` and the relational staff transaction; `staff-http.ts` already provides `PUT /api/v1/admin/versions/:version_id/questions/:question_id` and `POST /api/v1/admin/versions/:version_id/publish`, with Teacher approval for the version's subject. Publish creates the exact immutable version snapshot; only prompts/options go to Student metadata. An actual unpublished draft/version that Teacher owns or is authorized to write must already exist: no reviewed new-draft/demo provisioning path was found on this narrow pinned route.
2. `POST /api/v1/admin/assignments` already locks sorted people, then group, version and current DB clock, checks current role before receipt replay and writes assignment, membership-epoch grants, receipt/audit. The patch changes the two old Admin-only guards together, at storage load and on the canonical assignment domain: explicit, active scoped group and approved subject for Teacher, no broad scope shortcut, correct pre-existing Admin/Owner authority. The Teacher path uses the exact real published snapshot and Asia/Tashkent next-midnight; student IDs must already be currently eligible members in this same group. It does not broaden roster or subject grants or change receipts/timers/outcomes.
3. Existing `storage/prepared-student.ts` recognizes GET `/exams`, GET `/exams/:id`, POST `/exams/:id/attempts`, owned GET `/attempts/:id`, PUT `/attempts/:id/answers/:question_id`, POST `/attempts/:id/submit`, and owned GET `/attempts/:id/result`, with scoped state and canonical current series. `attempts.ts` creates the original full personal deadline; `student-wire.ts` returns own ordinary earned/max/percentage. This pilot does not invoke separate detailed review or bonus.

## Actual blockers / approval gates

- Default `runtime/cloudflare-entry.mjs` only permits registration/profile/exam list and explicitly uses unavailable scoring conversions. It does not mount staff authoring/assignment or Student detail/start/answer/submit/result. Existing Clerk configuration does not pass the required staff validator/routes; production content/assignment storage ACL/binding and accepted request/response contract are not yet verified. A separate dedicated navigation read connection is not authority for any of these writes.
- Ordinary display still needs a verified production NumericPresentation adapter consistent with approved arithmetic/rounding and own-only projections. Do not activate fixture numeric behavior or silently treat raw displayed binary values as verification.
- Real browser identity/authorized metadata/listings remain incomplete. Provisioning a new draft if none available, deploying a reviewed rollout, and any planned real-state validation require explicit approval of their actors, assignments and destination. For one real group, use an existing approved Teacher and eligible already-enrolled Students; if unavailable, do not assign roles, move members, or invent data. Existing test review-gate initialization is blocked teacher approval; automatic early admission close/review is a separate pending integration, not a prerequisite for calculating the ordinary score in the code. Do not silently call that feature complete.

## One end-to-end validation after explicit approval

1. Confirm the approved real Teacher, a real Fizika draft/version, one scope-matched eligible group and authorized registered Students; confirm expected time window. In a reviewed pilot environment, authenticate Teacher through existing Clerk identity (no second profile).
2. Write a real question with authorized content and valid answers/revision proof, publish the exact immutable version, assign only to approved real enrolled student IDs. Verify the same Teacher cannot act outside granted group/subject using read-only or explicitly authorized negative checks; Admin existing behavior remains independently available, not required for this Teacher assignment.
3. At the scheduled start, a designated Student opens the same assignment, starts once, saves one approved response, and submits. If the approved window permits, reopen before the personal deadline after group admission ends; verify same attempt ID, generation, saved response and personal deadline, not a second attempt. Do not start a second normal attempt as a test without explicit authorization. Do not inspect other students' records.
4. Read that Student's own result and compare earned/max/percent to the approved manual key without publishing it; only present ordinary score, no bonus/review key. Record observations/errors and approvals, not unreleased credentials or student identity. No claims based solely on static patch apply.
