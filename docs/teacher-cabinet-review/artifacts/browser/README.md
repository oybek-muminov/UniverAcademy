# Teacher web browser adapter: local candidate

Patch applies to pinned UniverAcademy main commit `3dbb714f2f758c7dbe03548a71c161718cf9cb53`. No module, page or configuration installs an identity provider or connects to a live API. Default `main.mjs` mounts without an integration and remains unconfigured.

`mountTeacherCabinet(root, integration)` takes programmatic verified-identity and server-read capabilities. The identity source owns same-person verification with its signed-in provider, stable opaque generation comparisons and optional real server revocation invalidation events. Authorized transport independently derives authentication from that provider integration; `expected` is a defense-in-depth local match, never a credential or caller-selected account in a network request. There is no browser token transfer, redirect, URL, storage, new Clerk setup, or mutation except the already existing adapter-owned sign-out action with an expected generation check. Production still needs same-person browser handoff, a canonical read contract and scope-filtered authorization for all reads/actions.

The tentative envelope is `{status, data}`; 200 data is exactly `{person_id, name, access, subjects, groups, tests}` with `access={teacher, approved, enabled}` and narrow id/title rows. 401/403 or mismatched/disabled identity never show data. Unknown status, malformed shapes, excessive list sizes, duplicate row IDs, or stale/aborted responses fail closed. These fields/limits are a review projection, not a proposed replacement of any accepted HTTP schema. No generic group/test data is filtered by client as authority.

An identity or available grant event invalidates the current operation and immediately clears the rendered view (including during sign-out); fresh authorized read follows unless hidden. Hide/page restore and manual retry likewise clear/revalidate. The adapter does not claim instant detection of remote grant revocation when no server signal exists; the live server must deny revoked requests and the next read clears the view. Initial production entry hides Student switching and still preserves old view action support for separately configured callers. No live authorization, backend deployment, role-management implementation, or tests using synthetic data were attempted.

Static validation: pinned Git source hashes, strict patch apply and exact forward tree comparison, reverse applicability, `node --check` for affected JavaScript modules, and the repository's static copy build run in a temporary directory with pinned index/style source. No browser, authentication or server integration tests were run.
